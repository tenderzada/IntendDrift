# IntentDrift 论文潜在不足分析

> 对标 NeurIPS Datasets & Benchmarks Track 审稿标准和已接收论文（如 τ-bench、ScienceAgentBench、ToolComp、ChatChecker 等），逐维度分析本文的潜在弱点。

---

## 1. 数据集实际可用性（Accessibility）— 严重

**审稿标准要求**：数据集必须在审稿时可访问，托管在 Hugging Face、Kaggle、Dataverse 等持久平台上，附带 Croissant 元数据（[NeurIPS 2025 D&B CFP](https://neurips.cc/Conferences/2025/CallForDatasetsBenchmarks)）。84% 的已接收论文在投稿时就已在公开平台托管数据集（[NeurIPS Blog](https://blog.neurips.cc/2025/12/05/neurips-datasets-benchmarks-track-from-art-to-science-in-ai-evaluations/)）。

**我们的问题**：
- 当前 benchmark 的 576 个场景尚未实际生成（pipeline 代码存在但未执行）
- 没有公开数据集链接、没有 Hugging Face/Dataverse 托管计划
- 缺少 Croissant 元数据文件
- 缺少 datasheet / data card 等标准化文档

**对比**：τ-bench 在投稿时即提供了完整的 GitHub 仓库（[github.com/sierra-research/tau-bench](https://github.com/sierra-research/tau-bench)）、可运行代码和数据。

**建议**：在投稿前必须运行 pipeline 生成完整数据集，托管到 Hugging Face，制作 Croissant 元数据和 datasheet。

---

## 2. 数据构建的人工验证深度不足 — 严重

**审稿标准要求**：审稿人需评估"数据集是否构建合理"（[NeurIPS D&B Review Guidelines](https://neurips.cc/Conferences/2023/DatasetsAndBenchmarks/ReviewGuidelines)），特别关注 Layer 3（人工标注）的实际执行细节。

**我们的问题**：
- 论文声称"双人工标注，Cohen's κ ≥ 0.75"，但这些数字目前是**计划值/占位符**，非实测值
- 没有描述标注员的招募、培训、报酬等信息
- 没有实际展示标注分歧样例及裁决过程
- 人类基线（8名研究生，ITA=92.4%, ASR=87.1%）也是占位符

**对比**：已接收论文如 ScienceAgentBench 详细报告了标注流程、标注员背景、标注时间、分歧率和裁决案例。

**建议**：必须实际执行人工标注并报告真实 κ 值；描述标注员背景和培训；展示 2-3 个标注分歧的裁决案例。

---

## 3. 实验结果为占位符 — 严重

**审稿标准要求**：审稿人需验证"评估方法和实验设计是否合适且正确执行"。

**我们的问题**：
- 主实验表格（Table 1）、消融实验、框架对比中的所有数字均为**占位符**
- 案例分析（Case Studies）是设计出来的而非真实代理运行结果
- 无法验证核心发现是否成立（如"T3 和 T6 最难"、"意图漂移导致 22% 性能下降"）

**建议**：这是投稿前的硬性要求——必须完成完整实验。

---

## 4. 评估指标缺乏充分验证 — 中等

**审稿标准要求**：对 benchmark 论文，审稿人评估评估方法是否"appropriate and performed correctly"。

**我们的问题**：
- 6 个指标中，ITA/ASR/GDS 依赖 LLM-as-Judge，但仅在 50 个样本上做了初步校准
- PCR 的实现过于简化（基于关键词匹配），可能不够鲁棒
- GDS 的实现也是基于关键词（"unfortunately"、"alternative" 等），学术严谨性不足
- 缺少指标间的相关性分析（如 ITA 和 ASR 是否高度相关？如果是，权重分配的合理性存疑）
- IDS 综合评分的权重（0.25/0.15/0.25/0.15/0.10/0.10）缺乏理论依据

**对比**：τ-bench 的评估直接比较数据库终态（确定性评估），避免了 LLM-as-Judge 的可靠性问题。ChatChecker 虽使用 LLM 评估，但做了更大规模的人工对齐验证。

**建议**：
- 扩大人类-LLM 一致性验证样本至 200+
- 分析指标间相关矩阵
- 为 IDS 权重提供消融/敏感性分析的实际结果
- PCR 和 GDS 应升级为 LLM-judge 而非关键词匹配

---

## 5. 数据构建的同源偏差（Source Bias）风险 — 中等

**审稿标准要求**：数据集构建方法的合理性。

**我们的问题**：
- 虽然论文强调用不同 LLM 生成和验证来避免同源偏差，但整个 pipeline 从种子任务、蓝图、轨迹到验证全部依赖 LLM
- "由 LLM 生成的漂移场景"可能系统性地偏向 LLM 容易产出的模式，导致 benchmark 本身对某些代理有利
- 缺少与**真实用户对话**的分布对比——现有基准如 WildToolBench 从真实用户日志中提取数据，而我们完全是合成的
- Lost in Simulation（我们自己引用的论文）恰好论证了 LLM 模拟用户的不可靠性

**对比**：WildToolBench 从 ToolBench 的真实使用日志中提取行为模式；τ-bench 虽然也用 LLM 模拟用户，但承认了这一局限并通过 pass^k 指标量化不一致性。

**建议**：
- 增加一个小规模的真实用户意图漂移收集实验（即使只有 20-30 个场景），证明合成数据分布与真实分布的一致性
- 或至少用 WildToolBench 的公开数据做漂移模式的分布对比

---

## 6. 分类体系的完备性和必要性论证不足 — 中等

**审稿标准要求**：与先前工作的关系是否清晰（[Review Guidelines Q7](https://neurips.cc/Conferences/2023/DatasetsAndBenchmarks/ReviewGuidelines)）。

**我们的问题**：
- 六类漂移（T1-T6）的划分是否穷尽？论文没有论证为什么恰好是这六类（为什么不是五类或七类）
- 与 TUNA 框架（57 种请求类型）的映射较为粗略，缺少严格的映射表
- 缺少从真实对话数据中做频率分析来验证这六类是否覆盖了真实世界的主要模式
- T1（渐进细化）和 T3（约束追加）的区别较微妙，论文承认区别在于"部分执行已发生"，但这更像是时机维度的差异而非类型差异

**对比**：TUNA 框架从大量真实用户交互中归纳出分类体系，有数据支撑；ChatChecker 的用户角色虽然更简单，但每种角色都有明确的行为学支撑。

**建议**：
- 对一个小规模真实对话语料做意图漂移标注，统计各类型的频率分布
- 更严格地论证六类的 MECE 性（互斥且完备）
- 提供 T1 vs T3 的更清晰的判别标准

---

## 7. 规模和领域覆盖的说服力 — 低-中等

**我们的问题**：
- 576 个场景看似不少，但按 6 种漂移类型 × 8 个领域 × 3 个难度级别分解后，每个细分单元仅约 4 个场景
- 每个领域仅 18 个种子任务，多样性可能不足
- 工具都是模拟的（simulated API），不是真实 API——审稿人可能质疑其生态效度

**对比**：ToolBench 提供 16000+ 真实 API；τ-bench 虽然只有 2 个领域但每个领域有完整的策略文档和真实数据库；ScienceAgentBench 虽然只有 44 个任务但每个都经过专家深度验证。

**建议**：
- 强调质量优于数量的设计理念
- 考虑与 1-2 个真实 API 集成做验证实验
- 增加每个细分单元的场景数量（至少 8-10 个）

---

## 8. 负责任 AI（RAI）文档不足 — 低-中等

**审稿标准要求**：必须讨论伦理影响、偏见、负面社会影响（[NeurIPS 2024 D&B CFP](https://neurips.cc/Conferences/2024/CallForDatasetsBenchmarks)）。RAI 元数据的采纳率低是 [NeurIPS 博客](https://blog.neurips.cc/2025/12/05/neurips-datasets-benchmarks-track-from-art-to-science-in-ai-evaluations/) 指出的普遍问题。

**我们的问题**：
- 附录 E 有基本的伦理声明，但缺乏系统性的 datasheet/data card
- 没有分析合成数据中的潜在偏见（例如，LLM 生成的漂移场景是否存在文化偏见、性别偏见等？）
- 没有讨论 benchmark 被滥用的风险（如用来训练"操纵用户意图"的模型）

**建议**：
- 制作标准 datasheet（参考 Gebru et al., 2021）
- 添加合成数据偏见分析（至少做一个简单的词频/主题分析）
- 在 Broader Impact 中讨论更多具体风险

---

## 9. 写作和呈现的小问题

- 论文标题和摘要提到的模型数量（"12 models"）、场景数量（"500+"）等需与正文一致
- 部分 citation key 不一致（已修复但需 double check）
- 缺少 Figure 1（motivating example）和 Figure 2（radar chart）——论文中仅写"[Figure to be generated separately]"
- 附录 D 的表格全是占位符（"--/--"）

---

## 10. 与最新竞争工作的差异化不够尖锐

**我们的问题**：
- 2026 年初有大量相关工作涌现（AgentDrift、WildToolBench、τ²-bench、Lost in Simulation 等）
- 虽然 Related Work 做了对比，但差异化论证可以更尖锐：
  - WildToolBench 已包含 "instruction transition" 概念——我们需更清晰地说明为什么这不够
  - ChatChecker 的非合作用户已经涵盖"改变意图"的行为——我们需说明我们的系统性优势
  - τ²-bench 的 dual-control 框架在概念上也允许用户意图变化——需要更细致的区分

**建议**：在 Related Work 的对比表中增加更多细粒度的维度（如：是否有漂移点标注？是否有漂移类型分类？是否有过程级指标？），让差异一目了然。（这部分表格已有，但可以进一步细化。）

---

## 总结：优先级排序

| 优先级 | 问题 | 投稿前是否必须解决 |
|--------|------|-------------------|
| P0 | 实验结果为占位符 | 必须 |
| P0 | 数据集未实际生成和公开 | 必须 |
| P0 | 人工标注未实际执行 | 必须 |
| P1 | 评估指标的人工验证不充分 | 强烈建议 |
| P1 | 同源偏差风险需要缓解 | 强烈建议 |
| P1 | 图表缺失 | 必须 |
| P2 | 分类体系完备性论证 | 建议改进 |
| P2 | RAI 文档补充 | 建议改进 |
| P2 | 数据规模/真实 API | 条件允许时改进 |
| P3 | 差异化论证细化 | 投稿前打磨 |

核心结论：**论文的 framing（问题定义、分类体系、指标设计）目前质量较高，与已接收论文相当。但最大的硬伤是缺少"实质"——数据集未生成、实验未跑、人工标注未做。** D&B Track 的审稿人最看重的是可用的、可复现的 artifact，而非方法论创新。建议在 W2-W4 集中精力完成 pipeline 执行和实验。
